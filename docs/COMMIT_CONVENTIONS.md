# Конвенции коммитов и веток

## Conventional Commits

Формат: `тип(область): описание` — описание в повелительном наклонении, без точки в конце.

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `docs` | только документация |
| `refactor` | изменение кода без смены поведения |
| `perf` | производительность |
| `style` | оформление без смены поведения |
| `chore` | обвязка: зависимости, конфиги, настройки |

- Область — зона проекта: `feat(tree): …`, `fix(planner): …`, `chore(scrape): …`.
- Ломающее изменение: `!` после типа (`feat(data)!: …`) плюс строка `BREAKING CHANGE: …` в теле. В этом проекте ломающим считается в том числе **смена формата localStorage** — она обнуляет прогресс у живого пользователя.
- Один коммит — одно логическое изменение.
- Пересборка данных (`npm run scrape`) коммитится отдельно от кода: диффы в `src/data/` огромные и в одном коммите с логикой ревью не поддаётся.

## GitHub Flow

- `main` — всегда рабочий; напрямую в него не коммитят.
- Ветки: `feature/<слаг>`, `fix/<слаг>` → PR в `main` → merge после проверки.
- Ветка `gh-pages` — машинная, её ведёт `gh-pages -d dist`. Руками не трогать.
- Версии — SemVer. Релиз фиксируется в `CHANGELOG.md` и в поле `version` файла `package.json`.

## Что проверяет pre-commit

Хук лежит в `.git/hooks/pre-commit` (не husky: husky требует установленных зависимостей, а проверка нужна с первого коммита).

1. **oxlint по застейдженным** `.ts/.tsx/.js/.jsx`. Пока `node_modules` нет — шаг пропускается молча.
2. **`gitleaks protect --staged --redact`** — скан секретов. Если gitleaks не установлен, коммит **отклоняется**: тихо пропускать проверку секретов хуже, чем прервать работу. Установка: `brew install gitleaks`.

Хук живёт в `.git/`, то есть **не клонируется вместе с репозиторием**. На новой машине его нужно поставить заново — иначе проверок не будет, а выглядеть будет как будто всё в порядке.

### Когда pre-commit не пускает

- **gitleaks нашёл секрет** — это не повод добавлять исключение. Убери секрет из кода, положи в переменную окружения. Если находка ложная, добавь точечное правило в `.gitleaks.toml` с комментарием, почему это не секрет.
- **oxlint ругается** — почини. `npm run lint` покажет то же самое по всему проекту.
- **Обход `--no-verify`** — только когда точно понимаешь, что делаешь, и коммит всё равно не уйдёт в `main` без проверки.

## Роли инструментов

- **Локальные коммиты** — обычный `git` в Bash. `git add` разрешён без спроса, `git commit` и `git push` спрашивают подтверждение (`.claude/settings.json`).
- **GitHub MCP** — PR, issues, работа с удалённым репозиторием. Настроен в `.mcp.json`, токен только через переменную окружения `GITHUB_PERSONAL_ACCESS_TOKEN`.
