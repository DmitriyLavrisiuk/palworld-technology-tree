# Модель данных

Типы зеркалят строку игровой таблицы `DT_TechnologyRecipeUnlock` (структура `PalTechnologyRecipeUnlockDataTableRow`). Версия игры, к которой всё сверено, — `1.0.3`, она же лежит в `gameVersion` файла `chains.json`.

## Технология (`Technology`)

| Поле | Смысл | Диапазон |
|---|---|---|
| `id` | ключ строки DataTable, стабилен между патчами | `Special_PalSphere_Grade_03` |
| `name`, `description` | `{ ru, en }` | — |
| `level` | `LevelCap`, уровень персонажа | 1–80 |
| `cost` | цена в очках | 1–9 |
| `ancient` | `IsBossTechnology` — платится древними очками | 51 из 588 |
| `category` | `Items` или `Structures` | — |
| `group` | категория по классификации игры | 11 значений |
| `iconName` | слаг иконки из DataTable | **не использовать для URL**, см. ниже |
| `reqTech` | `RequireTechnology` — единственные настоящие рёбра | 17 штук |
| `reqBoss` | `RequireDefeatTowerBoss` | 17 штук |
| `reqResearch` | `RequireResearchId`, исследование лаборатории | 10 штук |
| `unlockBuild`, `unlockItems` | что открывает | ровно одно из двух непусто |

## Категория предмета

`group` берётся из пути ассета иконки, который задаёт сама игра:
`T_icon_buildObject_*`, `T_itemicon_Weapon_*`, `T_itemicon_Material_*`, а
снаряжение палов лежит в каталоге `PalIcon/`. Это **данные, а не наше
толкование** — множество `group === "structure"` в точности совпадает с
множеством `category === "Structures"`, хотя источники независимы. Инвариант
закреплён тестом.

| Категория | Технологий |
|---|---|
| `structure` | 217 |
| `palgear` | 124 |
| `weapon` | 90 |
| `armor` | 43 |
| `ammo` | 31 |
| `material` | 23 |
| `sphere` | 16 |
| `essential` | 16 |
| `accessory` | 12 |
| `consumable` | 11 |
| `glider` | 5 |

Следствие игровой классификации, которое удивляет: **топоры и кирки — это
`weapon`**, щиты — `armor`, отдельной категории «инструменты» в игре нет.
Раньше секции строились нашей эвристикой по словам в названии, и «инструменты»
там были; эвристика удалена.

## Инварианты

- Каждая строка заполняет **либо** `unlockBuild`, **либо** `unlockItems` — никогда оба и никогда ни одного. На этом стоит вывод `category`.
- Все `reqTech` указывают на существующий `id` — висячих ссылок нет (проверено).
- `id` уникальны и стабильны; связывать что-либо по названию нельзя, названия меняются с локализацией.

## Ловушки

**Пререквизитов почти нет — их 43, а не «дерево».** Ровно **545 из 588** технологий не имеют ни `reqTech`, ни `reqBoss`, ни `reqResearch` и гейтятся только уровнем и очками. Это главный факт всего проекта: дерева как графа в игре не существует.

> В документации прототипа стоит число 544. Оно получено как 588 − (17 + 17 + 10) и ошибочно: `Special_ElectricHatchingPalEgg` несёт два гейта сразу, поэтому технологий с хотя бы одним гейтом 43, а не 44. Верное число — **545**.

**`iconName` не резолвится на CDN.** Примерно пятая часть слагов даёт 404. Иконки скачиваются по URL со страницы списка технологий paldb и сохраняются под `id` технологии, а не под `iconName`. Обращаться к иконке следует по `id`.

**Поле `Tier` в исходной структуре бесполезно.** Оно равно 0 во всех 588 строках и игрой не используется — в типах оно намеренно не смоделировано, не возвращать его «для полноты».

**У 61 технологии нет рецепта.** Это сёдла и наборы: на paldb у них нет секции Production. `recipes.json` содержит 527 записей, и отсутствие записи — норма, а не сбой парсера.

**paldb отдаёт заглушку вместо непереведённого названия** — строку вида `ru_Text`. Парсер отбраковывает её в названиях технологий, станций и материалов; где русского имени нет, остаётся английское. Русские имена в рецептах выводятся из карты имён **на каждом прогоне**, а не берутся из прошлого файла: рецепты переиспользуются целиком, и однажды записанная заглушка иначе жила бы в данных вечно. Инвариант закрыт тестом.

**DataTable авторитетен по числам, paldb — по названиям.** Расхождение по `level` или `cost` между ними означает, что один из источников отстал на патч; парсер об этом предупреждает, но не чинит сам.

## Рецепт (`Recipe`)

`techId`, список `stations` из `{ id, name }` (пусто у построек — их строят, а не крафтят, это закреплено тестом) и `materials` с `{ id, name, count }`.

`id` станции — слаг страницы предмета, по нему лежит иконка в `public/icons/stations/`. Каталог отдельный от материалов и технологий: слаги могут совпасть. Русские названия материалов подтягиваются из отдельной карты имён paldb (~1900 записей); если перевода нет, остаётся английское.

## Цепочки (`ChainsFile`)

`chains`, `buckets` и `loose` — устройство и правила описаны в `CHAINS.md`. Здесь важно только одно поле: **`confidence`**. Оно говорит, откуда взялась связь, и обязано доезжать до интерфейса — на нём стоят пометки достоверности.

## Пал (`Pal`)

Типы зеркалят строку `DT_PalMonsterParameter`. Источник правды — `src/types/pal.ts`.

| Поле | Смысл | Диапазон |
|---|---|---|
| `id` | ключ строки таблицы, он же `data-pal-id` на paldb | `SheepBall` |
| `dexNo` + `dexSuffix` | номер в Палдексе; суффикс у стихийных вариантов | `121` + `B` |
| `name` | `{ ru, en }` из дампа локализации | — |
| `elements` | одна или две стихии | 9 значений |
| `work` | только ненулевые уровни работ | 13 ключей, уровни 1–8 |
| `nocturnal` | работает ночью | 76 из 288 |
| `food` | расход еды | 1–9 |
| `description` | `{ ru, en }` из дампа локализации | — |
| `passives` | врождённые пассивки, тексты — в `PalsFile.passives` | 23 разных у 53 палов |
| `size` | `XS`…`XL` | — |
| `transportSpeed` | скорость переноски | — |

**Контрольные суммы:** 288 палов, 13 работ, 9 стихий, уровни работ 1–8.

### Ловушки

- **Вместимости переноски не существует.** Ни в одном из 90 полей таблицы, ни на странице пала у paldb. `transportSpeed` — это скорость, а не «сколько предметов за раз»: подпись в интерфейсе должна называть вещь своим именем.
- **Уровень работы доходит до 8**, хотя базовый максимум в игре четыре: стихийные варианты выше. Верхняя граница шкалы в фильтре вычисляется из данных, а не задаётся константой.
- **`Astralym` — единственный пал без стихии и без работ**: в таблице у него `ElementType1` равен `None`. Исключение зафиксировано в тесте поимённо.
- **Нефтедобычей не владеет ни один пал.** Поле в таблице есть, но во всём Палдексе оно нулевое, поэтому работа не показывается в фильтре и иконки для неё не существует. Инвариант под тестом: появится владелец — тест упадёт.
- **Ключи работ и стихий — игровые** (`Handcraft`, а не `Handiwork`; `Leaf`, а не `Grass`). Они же служат ключами локализации, поэтому своих названий мы не заводим.

## Дроп (`DropResource`)

Источник правды — `src/types/drop.ts`; данные — `src/data/drops.json` из `DT_PalDropItem` (только базовая строка `Level 0`).

| Поле | Смысл | Пример |
|---|---|---|
| `id` | игровой id предмета, он же ключ локализации и имя файла иконки | `Wool` |
| `name` | `{ ru, en }` из `items.json` дампа локализации | «Шерсть» |
| `sources[]` | палы-источники: `palId`, `min`–`max` за убийство, `rate` — шанс в процентах | — |

**Контрольные суммы:** 100 ресурсов, 577 источников; дроп есть у 287 из 288 палов — единственное исключение `DrillGame` зафиксировано в тесте поимённо.

Порядок источников в данных — как в таблице игры; сортировка «лучший добытчик первым» (среднее количество × шанс) — presentation-логика в `src/lib/drops.ts`, под тестами.

## Ферма (`RanchProducer`)

Источник правды — `src/types/ranch.ts`; данные — `src/data/ranch.json` со страниц палов paldb (в зеркале игровых таблиц продукции фермы нет).

| Поле | Смысл | Пример |
|---|---|---|
| `palId` | пал с работой «Фермерство» | `SheepBall` |
| `products[].itemId` | что производит; имена — в словаре `items` файла | `Wool` |
| `products[].unlockLevel` | с какого уровня партнёрского навыка появляется | 1, у сфер Викси 3–5 |
| `products[].min`–`max` | количество за цикл на уровне появления | ×1 |
| `products[].min10`–`max10` | количество на 10-м уровне навыка — потолок | 3–10 |
| `products[].rate` | шанс в процентах, бывает дробным | 59.524 |

**Контрольные суммы:** 29 производителей — все палы с работой «Фермерство», 42 продукта. Инвариант под тестом: пал с фермерством без продукции — ошибка.
