# Конвейер данных

Одна команда собирает всё: `npm run scrape`. Выход — `src/data/*.json` и `public/icons/`. Оба каталога **генерируются**: править их руками бессмысленно, правка живёт до следующего запуска (закрыто на запись в `.claude/settings.json`).

## Источники

| Источник | Что даёт | Почему он |
|---|---|---|
| **DataTable** — зеркало `DT_TechnologyRecipeUnlock` на GitHub (`CreativeTechGuy/PalworldDBIndex`) | числа: уровень, цена, `ancient`, пререквизиты, что открывает | сама игровая таблица, один запрос вместо распаковки `.pak` |
| **paldb.cc** | названия, категории, рецепты, URL иконок | свежее всего по названиям; единственный источник рецептов |
| **Дамп локализации** — `oMaN-Rod/palworld-save-pal` на GitHub | описания на RU и EN | в DataTable описания лежат ключами локализации, а не текстом |

Авторитет распределён намеренно: **числа берутся из DataTable, названия — из paldb**. Расхождение между ними означает, что один из источников отстал на патч, и парсер об этом предупреждает.

## Палы

Данные раздела «Навыки палов» идут из тех же трёх источников: числа из зеркала (`DT_PalMonsterParameter`), имена и названия работ и стихий из дампа локализации (`pals.json`, `work_suitability.json`, `elements.json`), портреты со страницы `paldb.cc/en/Pals` одним запросом.

Три вещи, которые легко сломать:

- **Ключи локализации расходятся с таблицей по регистру** — `SheepBall` против `Sheepball`. Джойн идёт по ключу в нижнем регистре; буквальный дал бы 407 совпадений из 753 и оставил Ламболла без русского имени.
- **Номер Палдекса не уникален.** У Ламболла есть служебный близнец `Quest_Farmer03_SheepBall`, у Лизпанка — версия для нефтевышки, всего 15 таких строк. Отбор идёт сверкой со списком paldb, а не масками id: маски были бы гаданием.
- **Иконки работ сопоставляются по `data-i18n`.** В выпадающем меню страницы палов у каждой работы стоит атрибут вида `common_work_suitability_emitflame` — тот же ключ, что в игровой таблице. Поэтому файлы называются игровыми ключами, а не номерами paldb. Иконок двенадцать: нефтедобычи в меню нет, ею не владеет ни один пал.
- **Зеркало отстаёт от игры.** Одиннадцати палов Якусимы в нём ещё нет, хотя на paldb они есть — зеркало помечено «частичная поддержка 1.0». Парсер про это предупреждает поимённо. Отсюда 288 палов, а не 303 и не 299.

## Стадии

Порядок фиксирован: `techs` → `icons` → `recipes` → `materials` → `chains`.

1. **techs** — сливает DataTable с двумя языками paldb и локализацией, сверяет контрольные суммы, пишет `technologies.json`.
2. **icons** — качает 588 иконок в `public/icons/`, имя файла — `id` технологии.
3. **recipes** — обходит страницы предметов на paldb, пишет `recipes.json`. Уже известные рецепты берутся из предыдущего файла и повторно не качаются.
4. **materials** — иконки материалов в `public/icons/materials/` и станций в `public/icons/stations/`. Отдельных запросов к страницам нет: картинка лежит прямо внутри ссылки на предмет и приезжает вместе с рецептом. Каталоги отдельные — шесть идентификаторов материалов совпадают с идентификаторами технологий и в общем каталоге затёрли бы их.

   Переиспользование прошлого `recipes.json` проверяет форму записи: смена схемы сама обесценивает кэш. Без этой проверки парсер падал на первом же рецепте, прочитав станцию старой формы.
5. **chains** — чистая арифметика без сети: `build-chains.ts` + `chain-overrides.json` → `chains.json`. Правила — в `CHAINS.md`.

## Флаги

```bash
npm run scrape                      # всё, с использованием кэша
npm run scrape -- --only=chains     # только пересобрать цепочки (без сети, секунды)
npm run scrape -- --only=techs,icons
npm run scrape -- --fresh           # игнорировать кэш и скачать заново
npm run scrape -- --limit=25        # ограничить число страниц рецептов, для отладки
```

`--only=chains` — рабочая лошадка при вычитке цепочек: сети не касается вообще.

## Кэш и вежливость к источникам

Скачанные байты складываются в `.cache/` под именем `<sha1(url)[:16]><расширение>`. Каталог в `.gitignore` — в репозиторий не попадает, но переживает перезапуски, поэтому повторный прогон не стоит ничего.

paldb.cc — волонтёрский фанатский сайт. В `scripts/lib/http.ts` стоит **сериализация всех запросов и пауза 220 мс** между ними, три попытки с возрастающей задержкой на 5xx и 429. Эти ограничения снижать нельзя: они там не ради нас.

## Обновление после патча игры

1. `npm run scrape -- --fresh` — полный прогон без кэша. Долго: около 1100 запросов с паузой.
2. **Прочитать предупреждения.** Расхождение контрольных сумм — не ошибка сборки, а сигнал, что игра ушла вперёд. Сверить новые числа с игрой и обновить константы в `src/lib/constants.ts` вместе с таблицей в `DATA_MODEL.md`.
3. `npm run typecheck` — схема могла поехать.
4. Посмотреть `git diff --stat src/data/` — размах изменений говорит, патч это или сбой источника.
5. Коммит данных **отдельно от кода**: диффы огромные, вперемешку с логикой они не ревьюятся.

## Что делать, если источник умер

Кэш в `.cache/` — единственная копия сырых страниц, и он локальный. Если paldb станет недоступен, пересборка рецептов и иконок сломается, а `technologies.json` — нет: числа лежат в зеркале DataTable на GitHub. Готового плана переезда нет; при необходимости он появится здесь.
