# Архитектура

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite 8 | Статика, мгновенный dev, из коробки code splitting |
| UI | React 19 + TypeScript | Проверено на этой задаче в прототипе |
| React-плагин | `@vitejs/plugin-react-swc` | см. ниже — babel-версия не встаёт рядом с `shadcn` |
| Стили | Tailwind v4 (`@theme inline`) | Токены прямо в CSS, без отдельного конфига |
| Компоненты | shadcn/ui, стиль `base-nova`, база Base UI | Требование к дизайну; 13 компонентов реально несущие |
| Иконки интерфейса | lucide-react | Библиотека по умолчанию у shadcn |
| Линтер | oxlint | Быстрый, конфиг в `.oxlintrc.json` |
| Тесты | Vitest | Конфиг `vitest.config.ts`; тесты рядом с кодом, без сети и без DOM |
| Парсер | tsx + cheerio | Запуск TS без сборки, надёжный разбор HTML |
| Публикация | gh-pages | Токен без scope `workflow`, см. DEPLOYMENT.md |

Форматтера в стеке нет: oxlint — линтер. Хук `PostToolUse` в `.claude/settings.json` вызывает `oxlint --fix`. Если понадобится настоящий форматтер, это отдельное решение с отдельной зависимостью.

## Структура каталогов

Существует сейчас (после Фазы 1):

```
scripts/
  scrape.ts             оркестратор стадий techs → icons → recipes → chains
  build-chains.ts       синтез цепочек, пять проходов (см. CHAINS.md)
  chain-overrides.json  ручные семьи и запреты — единственное место правок
  lib/                  http с кэшем и троттлингом, лог
  sources/              datatable, paldb, l10n, icons
src/
  types/tech.ts         типы предметной области
  lib/constants.ts      числа игры, геометрия сетки, порядок групп
  data/                 ГЕНЕРИРУЕТСЯ парсером, руками не трогать
public/icons/           ГЕНЕРИРУЕТСЯ парсером, 588 файлов
.cache/                 сырые страницы источников, вне git
```

Появится в Фазе 2 и далее: `src/hooks/` (`useProgress`, `useTheme`), `src/lib/` (`data.ts`, `planner.ts`, `i18n.ts`), `src/components/ui/` (shadcn) и `src/components/tree/` (узлы, режимы, шкала, панели).

## Ключевые технические решения

**Граф-библиотеки нет намеренно.** X узла задаётся уровнем, Y — строкой семейства, поэтому раскладка сводится к умножению на шаг сетки. React Flow пришлось бы переопределять целиком. `react-zoom-pan-pinch` тоже отвергнут: под CSS-трансформацией перестают работать липкие названия цепочек и линейка уровней, без которых шкала на 80 уровней нечитаема. Зум делается ступенчатым изменением шага сетки.

**React-плагин на SWC, а не на Babel.** `@vitejs/plugin-react@6` через `@rolldown/plugin-babel` требует `@babel/core@8`, а пакет `shadcn` тянет `@babel/core@7` — npm не разрешает такое дерево. `@vitejs/plugin-react-swc` поддерживает Vite 8, не зависит от babel вовсе и убирает из сборки весь babel-тулчейн. Это отличие от прототипа, где конфликта не было: там `@rolldown/plugin-babel` в дерево не попал.

**Тестируется чистая логика и данные, а не интерфейс.** Под тестами — инварианты сгенерированных данных и правила сборки цепочек; в Фазе 4 добавится планировщик. Компоненты не покрываются: для инструмента на одного пользователя поддержка таких тестов дороже пользы, а регрессии в раскладке всё равно видны глазами. Тесты не ходят в сеть — иначе они перестанут запускаться на каждом коммите.

**Данные грузятся динамическим `import()`.** Около 1 МБ JSON попадает в отдельные чанки, а не в основной бандл. Ориентир из прототипа: technologies ~74 КБ gzip, recipes ~16 КБ, chains ~6 КБ.

**Пути к ассетам идут через `import.meta.env.BASE_URL`.** Сайт живёт в подкаталоге GitHub Pages. Абсолютный путь от корня работает на дев-сервере и молча ломается на проде — ошибка воспроизводится только после выкатки.

**Единственный источник постоянного состояния — `useProgress` поверх localStorage**, один ключ, одна схема: отметки изученного, уровень персонажа, язык, режим, тема. Всё остальное — обычный React-стейт. Изменение формы хранимого объекта требует миграции, иначе у игрока обнуляется прогресс.

**TypeScript разделён на два проекта:** `src/` (bundler resolution, `tsconfig.app.json`) и `scripts/` + конфиг Vite (nodenext, `tsconfig.node.json`). Разные системы модулей — из-за nodenext в скриптах алиас `@/` не разрешается, там относительные пути с расширением `.ts`. `npm run typecheck` (`tsc -b`) проверяет всё, что подключено в `tsconfig.json`.

Сейчас подключён только `tsconfig.node.json`: приложения ещё нет. Ссылка на `tsconfig.app.json` и строка `vite.config.ts` в `include` добавляются в Фазе 2 — до тех пор `tsc -b` проверяет парсер и те файлы `src/`, которые парсер импортирует.

## 📖 Для человека

Почему не взяли готовую библиотеку для деревьев: в настоящем дереве положение узла определяется его связями, и библиотека нужна, чтобы эти связи распутать. Здесь положение узла известно заранее — это его уровень в игре. Распутывать нечего, а библиотека принесла бы свою систему координат, с которой пришлось бы бороться.
