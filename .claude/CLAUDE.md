# CLAUDE.md

Дерево технологий Palworld: 588 технологий, разбросанных по 80 уровням, пересобранные в цепочки апгрейдов вдоль шкалы уровней. Vite 8 + React 19 + TypeScript + Tailwind v4 + shadcn/ui, статика без бэкенда.
Полная документация в docs/. У каждого файла — контракт-шапка (на что отвечает, где источник правды). Начни с шапки; если файл релевантен задаче — читай целиком, кроме секций «📖 Для человека».

## Документация (читать по необходимости, не всю сразу)
| Файл | Когда читать |
|---|---|
| `docs/PROJECT_OVERVIEW.md` | старт новой фичи, непонятен контекст |
| `docs/ARCHITECTURE.md` | новый модуль, компонент, слой; стек и технические решения |
| `docs/ROADMAP.md` | планирование работ — текущая фаза и её задачи |
| `docs/UI_UX.md` | любой UI-компонент, режим, панель |
| `docs/DEPLOYMENT.md` | прод: выкатка, диагностика, ограничения GitHub Pages |
| `docs/COMMIT_CONVENTIONS.md` | оформление коммита, ветки, PR |
| `docs/STATUS.md` | начало любой сессии — что сейчас работает и что в процессе |
| `CHANGELOG.md` | почти никогда; только если нужна история изменений |

Файлы `docs/DATA_PIPELINE.md`, `docs/DATA_MODEL.md`, `docs/CHAINS.md` появятся в Фазе 1 вместе с переносом парсера — до тех пор источник по этим темам — прототип (см. ниже).

После завершения значимой задачи обнови `docs/STATUS.md` (перезаписью) и добавь строку в `CHANGELOG.md`. STATUS.md держи в пределах 50 строк. Выполненные задачи отмечай в `docs/ROADMAP.md`.
Секции «📖 Для человека» при работе над задачами пропускай.

## Прототип

`../palworld-tree-researching.loc` — работающий прототип этого же инструмента (репозиторий `DmitriyLavrisiuk/palworld-tech-tree`). Из него переносятся парсер, данные, иконки и технические решения. Это **справочник, а не образец для копирования**: код читаем ради выводов, но переносим осознанно. Причины, по которым проект пересобирается, — в `docs/PROJECT_OVERVIEW.md`.

## Команды
```bash
npm run dev         # Vite dev-сервер
npm run build       # tsc -b && vite build
npm run typecheck   # tsc -b по обоим проектам (src + scripts)
npm run lint        # oxlint
npm run scrape      # пересобрать данные и иконки из источников
npm run deploy      # сборка + публикация на GitHub Pages
```

## Принципы работы (обязательны)

1. **Думай до кода.** Не выбирай интерпретацию молча — если вариантов несколько, покажи их. Допущения называй явно; если что-то непонятно — остановись и спроси. Если есть более простое решение — предложи его.
2. **Минимализм.** Минимум кода, решающий задачу. Ничего спекулятивного: ни фич сверх запрошенного, ни абстракций для одноразового кода, ни «гибкости на будущее». 200 строк, которые могли быть 50 — переписать.
3. **Хирургические правки.** Трогай только то, что нужно для задачи. Не «улучшай» соседний код, комментарии и форматирование; не рефактори работающее; повторяй существующий стиль. Убирай только те импорты/переменные, которые осиротели из-за ТВОИХ правок. Замеченный чужой мёртвый код — упомяни, не удаляй.
4. **Goal-driven.** Превращай задачу в проверяемую цель до начала работы («исправь баг» → «напиши тест, воспроизводящий баг, добейся его прохождения»). Для многошаговых задач — краткий план, у каждого шага критерий проверки.

## Архитектурные правила (не дублируются линтером)

- **`src/data/**` и `public/icons/**` генерируются парсером.** Руками не править — правка живёт до следующего `npm run scrape`. Исправления цепочек вносятся только в `scripts/chain-overrides.json` с последующей пересборкой. Эти пути закрыты на запись в `.claude/settings.json`.
- **Достоверность связей — часть продукта.** 544 из 588 технологий не имеют пререквизитов в игре: почти все цепочки синтезированы. Синтезированная связь всегда помечена в интерфейсе. Выдавать эвристику за игровые данные нельзя ни в UI, ни в документации.
- **Пути к ассетам — только через `import.meta.env.BASE_URL`.** Сайт живёт в подкаталоге GitHub Pages; абсолютный путь от корня ломает прод, но на локальном дев-сервере выглядит рабочим.
- **Постоянное состояние — только `useProgress` поверх localStorage.** Один ключ, одна схема. Другие записи в localStorage не заводить. Меняешь форму хранимого объекта — предусматривай миграцию: иначе у игрока обнулится прогресс.
- **Граф-библиотеки не подключать.** Раскладка — арифметика по уровню и строке; React Flow пришлось бы переопределять целиком, а CSS-трансформации ломают липкую шкалу уровней. Считаешь, что случай исключительный — сначала обсуди.
- **Данные грузятся динамическим `import()`.** ~1 МБ JSON не должен попадать в основной бандл.
- **Проект некоммерческий и фанатский.** Иконки и названия принадлежат Pocketpair. Не добавлять монетизацию, рекламу, аналитику и трекеры.

## Стиль кода
- Компоненты — по одной ответственности на файл, имена по домену (`TechNode`, `LevelRuler`), без сокращений.
- Тексты интерфейса — только через словарь i18n, RU и EN одновременно. Строк в JSX быть не должно.
- Conventional Commits (`feat:`, `fix:`, `chore:`...), GitHub Flow (`feature/*`, `fix/*`). Подробности — `docs/COMMIT_CONVENTIONS.md`.
- Не пишем код-стайл правила, которые уже покрыты линтером — он работает за нас.

## Когда сомневаешься
Сначала опиши план и спроси подтверждение — не пиши код сразу, — если задача затрагивает:

- **парсер и схему данных** (`scripts/`, `src/types/`) — ломается всё приложение сразу;
- **формат localStorage** — ломается прогресс живого пользователя;
- **выкатку на прод** (`npm run deploy`, `base` в конфиге Vite) — Pages отдаёт сломанные пути молча;
- **правовую рамку** — источники иконок и названий, любые намёки на коммерческое использование.
